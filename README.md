# GitHub Pages 部署与手机 / 电脑手动同步

这是一份无后端的静态工作台。GitHub Pages 提供网页文件；你的计划、打卡、复盘、文献总结与附件保存在各设备当前浏览器。无需账号登录，也没有应用内的云端数据库或自动同步服务。

## 1. 发布到 GitHub Pages

1. 解压 `研习工作台_GitHubPages.zip`，只上传里面的文件。也可直接使用 `github-pages` 文件夹中的内容。
2. 在 GitHub 新建一个专门的仓库，例如 `study-workbench`。GitHub Free 使用公开仓库启用 Pages，因此仓库及网页源码会公开。仓库名请自行选择。
3. 上传 `index.html`、`.nojekyll`、`README.md`、`.gitignore` 到仓库根目录。入口必须是 `index.html`，不要上传 `site.template.html`，也不要再套一层文件夹。
4. 打开仓库 **Settings → Pages → Build and deployment**。
5. Source 选 **Deploy from a branch**，Branch 选 **main**、文件夹选 **/(root)**，点击 **Save**。若默认分支名不同，选实际上传文件的分支。
6. 等 GitHub 完成发布，在 Pages 页面打开它显示的网址，通常为 `https://你的用户名.github.io/study-workbench/`。把这个网址发到手机，即可在手机浏览器打开并加入书签。

本地已生成部署包，没有代替你创建仓库或发布。以后更新：运行 `python build.py`，把新生成的 `github-pages/index.html` 覆盖上传到同一个仓库根目录，发布结束后刷新网页。保持网址与浏览器不变，更新网页不会主动覆盖已有记录；更新前仍建议导出备份。

官方说明：[创建 Pages 站点](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[设置发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 2. 从现有电脑本地版迁移

1. 用原来使用的浏览器打开原 `dist/index.html`，点击“备份与恢复”或顶部备份按钮，导出完整 JSON。
2. 在浏览器打开刚发布的 HTTPS 网址，打开备份窗口，选择这个 JSON。
3. 核对显示的记录和附件数量，再点击“确认替换并恢复”。

本地文件地址与 HTTPS 网址属于不同存储位置，不会自动共享数据。换浏览器、域名或子域名，也要手动导入。

## 3. 电脑 → 手机 → 电脑

1. **电脑完成记录后**，导出完整备份。通过 USB、隔空投送、聊天文件传输或你选择的方式，将 JSON 文件传到手机。
2. **手机开始记录前**，打开同一个网站链接，在备份窗口选择此 JSON，核对后确认恢复。导入会替换手机旧数据。
3. **手机完成记录后**，重新导出一份备份。没有自动下载时，点“再次下载 JSON”；支持文件分享的手机浏览器还会显示“分享备份文件”。若打开文件预览，用浏览器系统菜单保存到“文件”。
4. 把手机生成的新 JSON 传回电脑；电脑先保留自己的当前备份，再导入手机这份新备份，继续工作。

**这是手动接力，不会自动合并两端修改。** 尽量一次只在一台设备上修改；切换设备时执行“导出 → 传递 → 导入”。不要同时修改后再用旧备份覆盖新记录。文件名含生成日期和时间，建议保留多个版本。备份中包含个人内容，请存放在自己信任的位置；通过第三方工具传输时，由该工具处理文件。

生成备份后继续修改页面，已生成的文件不会自动更新；离开设备前请再次导出最新版本。导入时会校验格式、记录和附件，确认前不更改已有数据。

## 4. PDF、截图和组会文档

- 完整备份包含浏览器里已保存的文件副本；导入后可在另一设备打开。PDF 会在单独页面打开，由浏览器或系统阅读器显示。
- `D:\Papers\paper.pdf` 这类原路径不能从网页网址或手机访问。请在文献编辑窗口选择 PDF，保存一份浏览器副本，再导出完整备份。在线版点击标题会自动打开这个副本。
- 仅填写路径但未保存副本的文献，仍会迁移标题与总结，PDF 本体不会迁移。
- 组会 PPT/PPTX 在手机上需要系统或其他已安装阅读器支持，网页不会转换格式。
- 单份文档最多 30MB；文献 PDF、截图与组会附件合计 100MB。完整备份上限 160MB，包含 Base64 文件内容，体积通常大于原文件总量。手机导出较大备份时需要可用内存和空间。
- 配套教材与练习代码没有放进部署包；在线版相应按钮会提示使用电脑本地版。完整自学指南已经内嵌，无需额外文件。

## 5. 数据边界

- 网页不会将你的计划、笔记、附件或 JSON 备份提交给 GitHub，也没有分析统计或自动备份接口。文字主要存于 localStorage，附件存于 IndexedDB。
- 浏览器存储由同源网页共享：不同浏览器 / 设备各有记录；同一个 `用户名.github.io` 下不同仓库路径属于同一个源。本工作台使用固定存储键，同源多份本工作台会共享记录，并非隔离账号。请使用一个固定网址；共享电脑同一浏览器也会看到相同记录。
- GitHub 仍会处理正常网页访问所需的请求和访问元数据。仅在主动使用“本机识别文字”时，浏览器会从外部 CDN 下载 OCR 程序及语言模型；当前识别代码在设备本地处理截图，不上传截图。若不需要，可直接手动填写要点。
- 不要上传 JSON 备份、PDF、截图或整个研究资料目录到公开仓库。部署包通过明确的文件清单生成，不含浏览器记录、附件或 QA 测试备份。`.gitignore` 只作辅助，网页上传仍需自行只选部署文件。
- 不要用无痕模式长期记录。清除站点数据、换浏览器、存储被系统回收或卸载浏览器可能丢失本地记录；导出的完整备份才是迁移与恢复凭据。
- 在线版首次打开及刷新需联网；没有配置离线缓存。电脑原本的本地 HTML 版仍可继续使用。

## 6. 发布内容清单

```text
index.html    正式网页，CSS 和 JavaScript 已内嵌
.nojekyll     让 Pages 直接提供静态文件
README.md     本说明
.gitignore    忽略个人备份和常见附件
```

本地源文件修改后请重新构建。不要将 QA 目录或真实用户数据加入发布清单。


## 闲置任务随备份迁移

每日与每周共用的闲置清单、其中保留的小任务、整个周任务的分日安排和复盘，也包含在完整JSON备份中。新版采用v10格式；可导入v1–v9旧备份，旧备份的闲置清单默认为空。更新后请一起刷新所有已打开的工作台标签页，避免旧网页继续写入旧格式。
